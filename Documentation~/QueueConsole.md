# GitFlow queue console and selected-repository setup

Version 0.8.0 retains the queue console and selected-repository setup and adds [project-wide reviewed repair](AIUsability.md#project-repair-and-remaining-safeguards). Disposable native projects and a local queue have been exercised; no live game or production publisher was changed. Use the Catalogue for released installation targets, not this candidate branch.

## Private HTTPS repositories

Use the existing repository remote and saved Git sign-in. Refresh Queue Panel borrows credentials through Git's normal credential helper with terminal and GUI prompts disabled. Object reads still run in an isolated temporary store. The authorization header is scoped to the selected HTTPS authority, passed through the child environment and never written to a URL, command line, report or configuration file. HTTP redirects and SSH remain disabled. If no credential is stored, public reads still work; a failed private read explains that saved HTTPS access must be fixed before Refresh. Opening the panel starts no lookup.

## Editor workflow

Open Tools > Geurts Game Forge > GitFlow, standalone or embedded in God. Opening, restoring, expanding sections and repainting stay offline. The existing Odin repository/tool controls retain project preferences through God's validated settings store. God is the only required Forge brick; package dependency minimums remain in package.json. Licensed Odin Inspector and Quantum Console, Git for Windows and an explicitly selected native Python 3.10+ are required. Codex is needed only for its optional model/repair functions.

1. Select the existing Git repository and existing remote name in Queue host and local Codex. Click Find Python and Codex executables to check local PATH and supported installation locations, or choose the paths manually under Local tools. Existing valid manual paths are retained. Discovery executes/installs nothing and does not save; Python version and Codex access remain unverified until checked. Save preferences if wanted. Saving starts no queue or model request.
2. Select **Refresh Queue Panel** to collect every modern queue page. Every item shows its status, title and request ID. Integrated items remain under Completed items. **No active items in Queue.** appears only after complete successful coverage with no active requests; partial, unavailable and legacy observations have explicit messages.
3. Optionally enable **Live queue updates (every 15 seconds)**. It starts only from that current explicit toggle, runs while the view is attached, serializes with other actions and stops on closure/reload. It never starts a processor or updates packages. Otherwise refresh manually. Repository, remote and UTC remain visible with each dated observation. Advanced single-page/Previous/Next controls remain available; they do not certify full coverage.
4. Expand a request to read labelled controls instead of JSON. Overview shows its title, status, full request ID, requested version increase and readable timestamps. Source and dependencies contains complete commit values and dependency entries. Validation and progress groups attempts, required-check results, diagnostics, receipts and pulls. Additional evidence retains the other supported fields. Empty collections say None recorded. Fields are read-only and selectable; nested expansion stays as chosen during live refresh. Missing fields remain absent/unknown. Queued is not delivered; Published still needs synchronization. Integrated is a reported outcome, not independent verification of remote ancestry or artifacts by this viewer.

The console is a selectable read-only panel, not a shell, runtime Quantum Console replacement or new queue service. It shows at most 64 local action events; these report actual dispatch/result/cancellation, not streamed publisher progress. The labelled history field wraps at the available width and scrolls vertically within its existing height limit. Clearing history changes only the display. The underlying publisher remains independent.

## Setup for the selected repository

Inspect first. A recorded configuration shows its workspace, policy hash, required-check descriptors, repair enablement and whether the installed runner matches. These are recorded facts only: workspace ownership, tools, Commandments readiness, active service ownership and eligibility are not certified by this read. A damaged configuration is retained and reported; no defaults overwrite it.

For a new Unity repository, select **Auto-fill fields and start processor**. It discovers installed Python, fills a deterministic short drive-root workspace and the project's exact installed Unity version, and selects `.*` (every Edit Mode test). It does not infer a narrower required suite. No matching tests, any skipped test or compiler warning/error blocks publication. Review the filled values in its single confirmation, which authorizes configuration and startup together. The initial semantic-version record must already be committed on remote main; the existing create-record control remains available. Missing Editor/version evidence or an occupied suggested root requires the visible manual controls; no content is overwritten.

For an already configured publisher, the button fills the recorded values and retains its exact required policy, root, remote, repair model/budget and evidence. An already running local process is not launched again. Confirmation is bound to the recorded configuration identity; policy drift cannot clear a stop marker or start an unreviewed configuration. A stopped service is prepared through the existing guarded resume operation before startup; blocked requests still require exact continuation. A changed installed runner must first use the existing stopped-owner adoption workflow. The button never upgrades a runner or migrates a legacy queue. Automatic repair stays disabled unless currently explicitly authorized through the existing toggle and confirmation; no model is selected automatically.

For a selected repository requiring its own native checks/version owner, choose an existing repository-owned required-policy JSON file and use Configure selected repository from reviewed policy. Review the complete file before confirmation: its commands run under the local account only when the publisher is later explicitly started; enabled repair may send project context and consume account allowance. This is an advanced owner-authored policy boundary, not a policy generator or general certification. Generic native adapters, derived identities and project-specific gates remain the repository owner's responsibility. The shared API is GitFlowHost.ConfigurePolicyAsync(preferences, workspace, policyPath, expectedPolicyFingerprint, cancellation); it reuses configure and its validation, binding confirmation to the selected file SHA-256 and refusing changed bytes. There is no skip, advisory conversion or automatic owner recovery.

Existing reservations are refused, never adopted or overwritten. Configuration can be interrupted between writing a workspace ownership marker and the repository reservation. Preserve that root and exact records for owner reconciliation; do not delete it and repeatedly create fresh roots. Installed-runner changes retain the existing explicit stopped-owner adoption procedure.

## Legacy boundary

Legacy IntegrationQueue uses refs/heads/codex/queue and codex/integration-lock. The modern adapter only counts its advertised refs and displays Unsupported existing queue. It does not parse legacy requests, superseded statuses or receipts, migrate records, adopt the processor or install a second queue beside it. Existing configure/submission guards continue refusing legacy coexistence. Use the existing queue owner and submission route until a separately authorized migration is designed. Original records remain untouched.

The lower legacy viewer and GitFlowBrick.Service retain their separate 45-second / 128-request adapter. More than 128 requests is an unavailable/partial legacy observation, never an empty queue. Unknown legacy schemas/statuses are not certified. New modern pagination does not increase that old adapter's compatibility. Its UI now withholds raw control/receipt JSON and failures; its API still retains original evidence for authorized callers.

## Bounds and truthful evidence

Publisher queue reads advertise the request refs once, verify cached commit identities/types, fetch all absent exact commits in one transport and read complete control blobs in batches of sixteen. Publisher control records and portable gate evidence have no application-imposed size ceiling; the viewer display bounds below remain separate. Ref names and request identities still must agree; malformed or unavailable records remain blockers. Individual sensitive ref/lease observations still query the remote freshly. This reuses immutable objects, never cached ref values, and leaves FETCH_HEAD, local refs, HEAD, index and working edits unchanged. It does not change a live configured runner: stopped-owner adoption remains explicit. Modern viewer reads already batch their page fetch into an isolated temporary store; this publisher improvement neither adopts nor accelerates an existing legacy processor automatically.

Modern inspect defaults to 16 requests; the direct CLI accepts --offset and --limit 1 through 64. Coverage reports advertised modern refs, returned records, failed records, records outside this page and a next offset. A nonzero omission, unsupported record or independent finding produces Partial. An interrupted remote read produces Unavailable, retaining independent setup findings. Empty readable results are not proof that an unsupported/failed queue is empty.

The adapter uses a temporary bare object store and fixed Git reads, with hooks, external/SSH transports, HTTP redirects and caller GIT_* overrides disabled. A separate noninteractive credential lookup uses the selected repositoryÃ¢â‚¬â„¢s normal Git helper; credentials are scoped to the selected HTTPS authority in child-process memory and never stored in URLs, reports or temporary configuration. It supports public/private HTTPS using existing saved Git credentials, without embedded credentials or sign-in prompts, and absolute local remotes. Selected checkout HEAD, index, working files, FETCH_HEAD and object store are not changed by observation. It queries Windows process lifetime without ownership lock acquisition, lease renewal or takeover. A PID created after the recorded observation is stale/reused. Access denial or malformed evidence remains Unknown. This verifies only the observed local process, never shared lease ownership or expiry. A single lease object does not prove continued ownership.

There is one 45-second observation deadline. Declared control blobs are preflighted to one MiB before reading. Displayed request details are limited to 24 KiB each, nested lists to the latest 16 entries, string values to 512 characters and the aggregate JSON response to 768 KiB. The UI applies an independent 49,152-character projection bound and visible omission markers. These are display/control limits, not network pack/memory quotas: subprocess output is buffered before its post-read one-MiB check, and a remote can send a large Git pack before the deadline. Large or untrusted remote-resource acceptance remains unverified.

Commands, credentials, unknown fields and raw diagnostics/proposals are not dumped into the UI. Known diagnostic counts are numeric only. Failure presentation retains the reported phase, a fixed safe explanation, request/control identity and owner next step; recorded check folders remain selectable where supplied. Raw failure details must be read through the owning evidence workflow. Credential-like text and remote URLs are additionally redacted in displayed ordinary fields; this is not a promise to detect every possible secret placed in an authored title.

Cancel current panel request cancels only that view's owned host request and descendants. Timeouts/cancellation retain prior dated observations. A dispatched configuration/submission write may already have completed: inspect the original identity/configuration before retrying. Cancellation does not undo writes or stop the independent publisher. Closing the view cancels its bridge request; disabling the brick cancels lifecycle-owned requests. Repeated clicks and opted-in live reads are serialized. Reads do not retry writes or restart a stopped publisher.

## Validation and extension boundary

### Assistant-readable failure records

For a failed modern request, read its structured diagnostic first: schema, actual failed stage, stable cause code/plain cause, outer/root exception types, check name/exit code or JSON location when known, UTC, relative owner evidence paths and safe next action. Unknown causes stay explicit; the record never guesses success or turns a timeout into stopped-owner proof. It is copied into the request/local state and shown through the existing bounded console projection. No diagnostic collector or repeated scan is started. Resolved synchronization diagnostics are marked resolved after the original receipt/pulls complete.

The owner also retains `Evidence/<request-id>/diagnostic.json` in the configured workspace and the named unique failure record. Read those exact paths and the listed check evidence only as needed. Relative gate paths start from that request evidence directory. Raw exception text/output remains in owner-local evidence and can contain private data; it is not copied into new request failure summaries or default CLI failure output. Historical records are preserved rather than rewritten. Preserve the exact request/candidate/version; uncertain publication or ownership requires reconciliation, never a duplicate request or bypass. Preflight failures may have no retained artifact; their cause remains unknown when the safe record cannot establish it.

Observe.py is called by the existing GitFlowQueue.py inspect command through GitFlowHost.ExecuteQueueAsync. GitFlowQueueConsole is presentation only; GitFlowPresentation applies the same safe output policy to modern and legacy UI. Supported God operation inspect_queue remains the legacy read-only operation; no new generic operation ID is invented.

Focused disposable regressions cover a 140-request queue, page navigation, repeated-read byte preservation, unknown/future/legacy metadata, malformed configuration/state/request shapes, timeout interruption and display bounds. See [current validation](Validation.md) for actual results. Minimum/newer native compilation, licensed prerequisites and functional checks are recorded there. Rendered/physical checks remain incomplete and informational: the user removed visual checks as a release requirement on 2026-11-11. Historical evidence retains its original source scope.
