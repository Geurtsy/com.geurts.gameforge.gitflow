# GitFlow 0.5.4 validation

Twelve focused real-Git/Windows checks cover the preserved publisher lifetime and affected queue/recovery boundaries. [Actual report](Evidence/0.5.4/DeploymentAcceptance.log) records the selected cases. The cache-removal case configures/adopts from a disposable package directory, starts the real CLI, deletes that directory inside the independent validation command, invokes the preserved native helper, then completes one source-bound repair of a file larger than 32 KiB. It verifies original source ancestry and restarts from the preserved runner after the original package is gone. Model proposals are controlled fixtures; no paid inference or account-capacity claim is made.

Two [native-diagnostic cases](Evidence/0.5.4/NativeDiagnosticsAcceptance.log) additionally verify that a large Unity.log supplies every native failure message alongside wrapper output, excludes ordinary progress chatter, and refuses unsupported/oversized native evidence before paid repair. The full raw native log stays in owner evidence; no matching diagnostic list is truncated.

The service case verifies that forwarding keeps the actual process PID and that explicit stop/resume and reviewed-configuration guards remain effective. Other cases retain changed/incomplete deployment refusal before ownership, exclusive stopped-owner adoption, idempotent delivery, post-publication recovery without a second version/retest, dirty-checkout preservation, original repair deadline/no-progress behavior, and read-only publisher/inspection policy.

Native C# behavior, assembly definitions, dependencies and the supported example are unchanged from published 0.5.3 at `1692edbaca9c95e32c05bd645c38fede7d4b2673`, apart from the version string. Its four Unity 6000.6.3f1 presentation checks, example compilation, full rebuild and 31-assembly default-diagnostic qualification are explicitly reused at executable candidate `7a3c2f727e1a1f822dacc054c6b51ffb0a74e6af`. [Machine-readable evidence](AIUsabilityValidation.json) retains the original native reports and separates fresh Python coverage. No rendered checks were performed.

Publication and consumer deployment remain separate. Existing publishers need an explicit Update and stopped-owner adoption before they gain this lifetime protection; no running executable, request, candidate, repair deadline, model or required validation policy is silently replaced. New owned Runner directories are retained rather than automatically deleted. Use the CLI/configured runner for long-lived production work, not direct imports from an ephemeral package cache.
