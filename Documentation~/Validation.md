# GitFlow 0.1.2 validation

Unity 6000.6.3f1 compiled the Git-resolved candidate and supported API example. Eight owning acceptance fixtures passed, zero failed/skipped. Exact candidate pins, source fingerprint and artifact hashes are in AIUsabilityValidation.json; the durable NUnit report is Acceptance-0.1.1.xml. Editor.log and the resolved fixture manifest/lockfile are release evidence assets. No test ran in a live consumer and no player build was created.

The new disposable project is C:\gf\gitflow-test. God was resolved from the authoritative catalogue commit 5e1c38f0be577c68bb4e49b0e872440d5015ac81. Required Odin 4.0.2.4 and QFSW.QC were reused privately from the user's existing validation assets; no vendor content is distributed. Git for Windows 2.56.0.windows.2 was used. Unity ran hidden with -batchmode -nographics -nosound from startup through shutdown. No mouse/keyboard injection, window activation, global audio change or Dreadvault processor operation was performed.

## Verified scope

- All five queue phases, released versus owned leases, source/version-matched receipts and actionable retained failures.
- Stopped recorded PID, stale report, malformed local/control data, unknown/future protocol and unavailable transport stay distinct and useful.
- Repeated refresh preserves every caller file's raw bytes and attributes, including index, config, FETCH_HEAD and untracked/unstaged changes; the disposable remote's files and refs are unchanged.
- Overlapping identical refreshes share one task, conflicting scopes and cooldown calls are refused, and temporary object stores are removed on normal/failure/cancellation paths.
- A real stalled loopback HTTPS helper is job-contained before launch; disposal completes within five seconds and closes the helper's socket. No publisher or repository script is launched.
- Installed God discovers exactly inspect_queue with no mutation/confirmation flags, offline admission changes no files, and actual async dispatch uses the enabled lifecycle service.
- A hidden UI Toolkit view uses the shared theme, retains the exact immutable API result, and exposes Help/failure sections. The complete supported example compiles. This is presentation-tree evidence, not rendered native acceptance.

Initial import/reference errors and read-only temporary-object cleanup failures were corrected before the final passing candidate. Their original logs remain separate failure evidence. The final source fingerprint excludes documentation-only evidence commits but includes implementation, fixtures and examples.

## Explicitly unverified and unsupported

Native rendered Editor geometry, normal/narrow and docked presentation, light/dark host skins, hover/physical keyboard focus and display scaling require a later authorized native review. No rendered conformance claim is made. End-to-end transient window visibility across vendor launchers is also unverified; source uses CREATE_NO_WINDOW, no interactive credentials, and suspended job assignment without desktop input APIs.

Actual lock ownership cannot be probed here because the existing queue's supported probe acquires a lock. Recorded PID presence therefore stays Unknown rather than Healthy. Missing PID evidence, remote-host liveness and lease expiry remain unknown where evidence cannot establish them. Lease dates never authorize takeover.

Validation claims/artifact content, current-main ancestry and native project behavior are not revalidated by this viewer. Private authentication, SSH and custom transports are unsupported; HTTPS credentials are never requested. Steam/bootstrap, player builds, submission, publishing, recovery and AI repair are outside this release. Consumer installation remains manual.
