# GitFlow publisher Help

## Help

Use the Publisher tab in Tools > Geurts Game Forge > GitFlow. Nothing starts when the window, God or Unity opens. The Inspector and Submit workflows retain their separate read-only and submit-once boundaries. Ordinary setup uses controls, without editing JSON or writing code.

1. Select the owning generic Git checkout and existing remote in Inspect. In Publisher, declare a repository-relative plain MAJOR.MINOR.PATCH file, all controller/gate paths to protect, and one to eight required validation commands. Each command has a unique lower_snake_case ID, a native console executable, literal arguments (one per line) and a 1–3600 second timeout. Use a silent/headless command and helpers; GUI/audio commands are unsupported. The tool hashes the executable. The file supports strict UTF-8, plain SemVer and one optional LF or CRLF. Other metadata formats need an owning adapter.
2. Review without saving. The read-only preview lists the exact policy/commands. Authorize Save reviewed policy file. Changed/malformed original policy or changed controls require a fresh review; saving never stages files or changes the branch/index. Commit/review the policy through that repository's normal Git workflow before queue use. The committed main policy controls publication; worker changes to that policy, declared controllers, versions or queue internals are rejected. Unknown policy fields are blockers.
3. Extract the matching immutable Windows runner ZIP, retaining all files and third-party notices. Select its GeurtsGitFlow.exe, a short empty dedicated root and reviewed remote URL/path. Configure stopped dedicated root, then explicitly Start independent publisher. The package-bound RunnerRelease manifest checks every released runner file. .NET 10 runtime is required; installation GUI errors are suppressed. The host runs without an open Editor or chat. It holds a root-exclusive OS lock and one persistent remote lease. Do not configure this against Dreadvault's existing processor root or legacy refs.
4. Workers commit a focused source, then use Submit with exact source/base, increment, title and complete scope/reason/dependencies/evidence/environment/unverified checks with next steps. After confirmation, retain its gf_<source> ID as Queued — awaiting integration and stop waiting. Repeated snapshots retain the original ID, version, receipt and failure; conflicting base/increment is rejected. No submission starts or wakes another publisher.
5. Inspect deliberately for a dated observation. Stop requests take effect between requests; they are not stopped-owner proof. After a real failure, preserve the original candidate, index, logs, control record and version. Resume original request once requires its exact ID and a reviewed changed-input/continuation reason. Normal saved configuration stays in all-request mode.

Public HTTPS inspection remains credential-free. Writes/private native transport may use GEURTS_GITFLOW_TOKEN supplied externally to the launched host's environment; this tool never saves it in God settings, command lines, receipts or gate environments. Credential helpers, interactive prompts, SSH and custom transports are disabled. Missing access remains an actionable failure. Use a trusted local remote for credential-free offline acceptance. Authentication acquisition is a separate operator action, never an unattended sign-in dialog.

## Generic project contract

The committed .geurts-gitflow.json uses schema 1, adapter generic_git, publication atomic_main, headless_silent_commands=true, version_file, protected_paths and gates. It cannot adopt a repository requiring PR review or immutable game releases; remote protections are still enforced. No alternate push, force update, gate waiver, credential fallback or AI repair is attempted. This adapter rejects submodules, symlink/reparse trees, ambiguous/non-ASCII task paths, unsupported version formats and dirty/ignored generated output. Required validation must leave the exact candidate HEAD/tree/index and files clean. Outputs belong in declared external logs/artifacts, not untracked candidate files. Nothing is blindly restored or deleted.

Native refs use refs/heads/geurts/gitflow/requests/gf_<exact-source>, lease and wip/<original-id>. GitFlowRecord.json is an immutable control tree whose parent lineage retains source/candidate history. Legacy codex refs remain read-only and are never claimed, migrated or changed. Queue/control evidence is bounded; the initial adapter stops at 128 retained records and needs an owning archive/paging extension beyond that limit.

Each request records the original exact source/base, policy fingerprint, increment, worker handoff and submission time. The publisher merges that source into current main, reserves one version above main and existing reservations, commits version metadata and fences its processing/WIP checkpoint before validation. Genuine source conflicts remain failed with their retained local index; unknown processor work is a processor preflight failure and leaves unrelated requests queued. There is no clean/reset/stash or automatic checkout replacement.

Every strict gate runs against the actual committed candidate through the same CREATE_NO_WINDOW, suspended-job-owned process runner. It records command/tool hash, complete retained stdout/stderr (32 KiB per stream), exit, times, OS/runtime, environment fingerprint, candidate/tree and policy identity. Logs exceeding portable bounds fail rather than fabricate portable evidence. Original local logs are retained under unique filenames. Worker claims remain historical; publisher gates run on combined/versioned inputs. Native/GUI/game coverage is only what the owning required commands actually establish.

Main and its publication receipt/result are pushed in the same atomic fenced transaction, then exact refs/commit types are fetched and verified. No sequential fallback exists. The integration checkout explicitly pulls --ff-only from the same remote. An optional originalCheckout can be declared through the public options API only; it is pulled only when already on main and completely clean. A blocked original pull preserves it and records published_pending_pull. With no configured original checkout, no worker checkout is modified. Public configuration is the narrow special case for explicitly opting into a second checkout; the normal no-code workflow deliberately configures no second checkout.

## Lease compatibility and recovery

Native lease protocol 1 has a 180-second owner/unchanged-observation interval, 20-second independent renewal cadence, 15-second per-transport bound and a 120-second outbound write/verification reserve. UTC fields are audit-only. Claims, renewals, takeover, release and every main/result/WIP write append ordinary fast-forward lineage. A lost sibling claim is busy contention. Unknown/future/legacy records and incompatible timings are blockers; no timestamp or missing PID authorizes takeover.

The host observes an unchanged successfully read lease object over the full local monotonic interval before abandoned-owner takeover. Observations reset on object/access/process changes. A healthy renewal resets the interval. The owner checks its deadline under one guard, prepares immutable objects, reserves the full write allowance immediately before transport, and verifies exact refs/objects before its prior deadline. Any rejection, timeout, late acknowledgement or uncertain verification permanently fences that owner. Exception cleanup uses the same fence; local evidence remains if remote failure recording cannot be verified.

Resume supports an unchanged clean recorded candidate on its original integrated main/policy, plus recovery of an already published matching receipt and pending pulls. It preserves IDs, assigned versions and all attempts (eight maximum), and never reruns a delivered version. Changed/conflicted/dirty candidates, changed main/policy, missing version checkpoints and ambiguous publication remain operator-visible blockers. Do not reset the root or submit a replacement ID. Comprehensive conflict repair, safe whitespace correction, native derived identities and committed-runner upgrade/migration are later capabilities, not silent recovery shortcuts.

A running executable is never upgraded by publication or worker submission. Explicitly stop between requests and prove its OS owner/descendants have exited before maintaining it. This release binds the root to runner/protocol 0.2.0/1 and rejects another runner version; automatic replacement/migration is unsupported. Keep the same root/settings/candidate/evidence for an owning future upgrade adapter. Optional AI repair remains unimplemented and disabled; no model is invoked or substituted.

## API and extension points

GitFlowBrick.QueueService and ConfigurationService are idle shared lifecycle services. GitFlowQueue.SubmitAsync(GitFlowSubmission) returns a verified original handoff once. GitFlowConfiguration.ReviewPolicyAsync creates an immutable exact-byte review; ApplyPolicy refuses stale originals. ConfigurePublisher writes only its explicitly stopped dedicated root. StartPublisher requires the trusted installed package's release manifest, checks its runner files, then starts an independent process. RequestStop writes only a graceful-stop request. Never trust a manifest supplied by an arbitrary runner folder.

GitFlowPublisher.RunAsync(options, serve, cancellation) is the same core compiled into the independent .NET host. It is an operator API, never a worker wait loop. Host commands are GeurtsGitFlow once|serve <reviewed-options.json> <outcome.json>. Scoped recovery options are transient and must not replace the saved all-request configuration. Future project adapters must own additional version stamps, PR/release workflows and native derived outputs rather than weakening this generic contract.

God operations inspect_queue, submit_request, apply_policy, configure_publisher, start_publisher and stop_publisher use these services. Inspect is offline admission; mutation execution requires the correct typed payload, confirmed=true, enabled lifecycle and God's current local foundation/conflict guard. Launch/stop acknowledgement is not verified health/stopped ownership. Core public service calls are explicit operator authority and retain their own exact-review, configuration, lease, process and publication guards.
